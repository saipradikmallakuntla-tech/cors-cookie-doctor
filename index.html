Origin is calculated from URLs. For cross-origin requests, supply the actual schemeful site relationship; the app does not guess public-suffix boundaries. This models fetch/XHR, not top-level document navigation. Do not enter live token or cookie values.

Cookie analysis asks whether a cookie with these attributes could accompany the supplied request, not whether the cookie was actually stored. Cookie values are never included in the report.

      Know the boundary
      No live requests are made. A simple cross-origin request can reach a server even when CORS blocks JavaScript from reading the response; a failed preflight normally prevents the actual request. Cookie handling is assessed separately.
      This is a standards-oriented diagnostic model, not a browser conformance certificate. Public-suffix validation, partition keys / CHIPS, private-network policies, redirects, service workers, browser-specific grace periods and storage access exceptions are not fully modeled. Domain-attributed and partitioned cookies can require additional context. Confirm results in browser developer tools.
      HttpOnly does not prevent the browser from sending a cookie. It prevents script access. Cross-origin and cross-site are different concepts.
